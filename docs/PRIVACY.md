# 개인정보·데이터 흐름

## 기본: 기기 밖으로 나가는 데이터 없음
로컬 기능(사진 선택·분석·추천·편집·내보내기)은 네트워크 요청을 하지 않는다. 코드상 네트워크를 쓰는 모듈은 `src/features/community/*`(Supabase)뿐이며, 환경변수가 없으면 클라이언트 자체가 생성되지 않는다(`SUPABASE_CONFIGURED`).

| 데이터 | 저장 위치 | 서버 전송 |
|---|---|---|
| 선택한 사진의 URI·크기·형식 | SQLite | 없음 |
| 촬영 시각 | SQLite (프로젝트에서 "촬영 시간 사용"을 켠 경우만) | 없음 |
| GPS·기기 등 기타 EXIF | **저장 안 함** (`normalizeAssets`가 촬영시각만 추출, 테스트로 확인) | 없음 |
| 480px 썸네일, 내보내기 사본 | 앱 문서 폴더 `cutpick/` | 없음 |
| 품질 지표·휘도 서명 | SQLite | 없음 |
| 취향 답변(고른 예시 사진 카드 id·파생 취향 태그 포함 — 예시 사진은 앱에 포함된 공개 라이선스 사진이며 사용자 사진이 아님), 학습 가중치, 행동 이벤트(최대 200건, 사진 데이터 없이 밝기/색 피처만) | SQLite | 없음 |
| 커뮤니티 게시 사진 | 사용자가 게시 화면에서 동의한 **한 장의 공유용 사본**(긴 변 1440px 재인코딩 + 480px 썸네일) | Supabase Storage |
| 이메일 | Supabase Auth (로그인용, 비공개) | 커뮤니티 사용 시 |
| 핸들, 하트, 신고, 차단 | Supabase DB | 커뮤니티 사용 시 |

## EXIF/GPS 제거
- 내보내기·업로드 사본은 원본 바이트를 복사하지 않고 `expo-image-manipulator`로 디코드→재인코딩한다.
- **런타임 가드**: `src/features/export-share/jpeg-metadata.ts`가 사본의 APP1(EXIF)·GPS IFD 존재 여부만 검사(좌표 값은 읽지 않음). 내보내기 사본에 GPS가 있으면 파일을 지우고 중단, 커뮤니티 업로드 사본에 GPS가 있으면 업로드 거부.
- **실기기 결과 (2026-10-18, Galaxy Z Flip5 / Android 16 / Expo Go 58.0.4)**: 사용자 실사진 3장 내보내기 — 원본(선택기가 넘긴 사본): EXIF 있음·GPS 없음 / 내보내기 사본: **EXIF 블록 자체 없음**(따라서 GPS 없음).
- **남은 검증**: 원본에 GPS가 실제로 있는 사진으로 확인하지 못했다(카메라 위치 태그가 꺼져 있거나, Android 선택기가 `ACCESS_MEDIA_LOCATION` 없는 앱에 위치를 가려서 넘긴 것으로 추정). iOS 미검증.
- Android 매니페스트에서 `ACCESS_MEDIA_LOCATION`·위치 권한 차단(app.json `blockedPermissions`).

## 권한
- 사진 선택: OS 선택기, 라이브러리 전체 권한 불필요(문서 기준). 앱은 보관함을 스캔하지 않는다.
- 사진 앱 저장: 쓰기 전용 권한만 요청(`requestPermissionsAsync(true, ['photo'])`).
- 카메라·마이크 권한 비활성(app.json).

## 삭제
- 설정 > 데이터 관리: 모든 프로젝트 삭제 / 모든 로컬 데이터 삭제(DB 전체 + 앱 파일 폴더).
- 프로젝트 삭제: 메타데이터·썸네일·내보내기 파일 삭제, 원본 사진은 그대로.
- 취향 초기화, 개인화 끄기, 학습 기록 삭제.
- 커뮤니티: 게시물 삭제(스토리지 파일 → DB 행 순서), 계정 삭제(내 스토리지 폴더 → `delete_my_account()` RPC: 하트·차단·게시물·프로필·auth 사용자 삭제, 내가 낸 신고는 작성자 정보 제거 후 보존).

## 로그
`logError`는 오류 코드와 이름만 남기고 URI·EXIF·이메일을 기록하지 않는다.

## 미검증 / 할 일

- 재인코딩 사본의 EXIF 실측 (미실행).
- 국외 이전 고지(Supabase 리전)와 처리방침 법률 검토.
