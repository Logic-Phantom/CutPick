# 기기 벤치마크

## 실기기 측정 — **미실행**
이 개발 환경(Windows 11, Android SDK·에뮬레이터 없음, macOS 없음)에서는 iOS/Android 실기기·에뮬레이터를 실행하지 못했다. 아래 표는 비어 있으며, 실측 전까지 권장 장수는 가설값(권장 100, 최대 300)이다.

| 기기 / OS | 장수 | 총 시간 | 사진당 | 피크 메모리 | 실패 | 측정일 |
|---|---|---|---|---|---|---|
| (미측정) | 30 | | | | | |
| (미측정) | 100 | | | | | |
| (미측정) | 300 | | | | | |

측정 방법(실기기에서):
1. `npx expo start` → Expo Go(또는 개발 빌드)로 실행.
2. 실제 사진 30/100/300장 선택 → 분석 화면 하단 "이번 분석 측정값: 사진당 약 N ms"를 기록(앱이 실제 경과시간으로 계산).
3. 메모리는 Xcode Instruments / Android Studio Profiler로 피크 측정.
4. 결과로 `IMPORT_LIMITS`(recommendation-policy.ts)를 조정하고 근거를 이 문서에 적는다.

## 참고: 비기기 측정 (2026-10-18)

### 웹 미리보기 (Chrome 계열 브라우저 패널, Windows 데스크톱)
- 샘플 18장 전체 파이프라인(캔버스 리사이즈 2회 + jpeg-js + 지표 + 서명): **사진당 약 254ms / 357ms**(두 번 실행). 앱이 직접 측정해 표시한 값. 모바일 성능을 대표하지 않음.

### 순수 TS 분석 코어 (Node 24, jest, `npm run bench`)
네이티브 리사이즈 제외, 128px JPEG 디코드 + 지표 + 서명 + 그룹화만. 샘플 18장을 반복 사용(중복이 많아 그룹화 조기 종료가 덜 일어나는 최악에 가까운 조건).

| 장수 | 디코드+지표+서명 | 사진당 | 그룹화 | heapUsed |
|---|---|---|---|---|
| 30 | 150 ms | 5.0 ms | 7 ms | 150 MB* |
| 100 | 365 ms | 3.7 ms | 57 ms | 161 MB* |
| 300 | 1052 ms | 3.5 ms | 438 ms | 74 MB* |

\* jest 프로세스 전체 힙이라 앱 메모리 추정에 쓰면 안 됨.
- 서명 캐시 도입 전 300장 그룹화는 10,977 ms였음 → 캐시·사전 디코드·조기 종료로 438 ms.
